# PKC 工作台统一联动实施计划

> 执行方式：当前会话内按阶段实施；用户已明确要求执行。此计划以批准的设计文档为准。

**目标：** 让队伍数据和当前场次上下文由统一服务维护，让跨页面导航使用稳定 ID，并逐步退役重复来源。

**架构：** 保持现有 JSON 与本地 Node 服务，在 `lib/` 建立领域服务；新接口提供规范写入，旧 API 作为兼容适配器。页面显式读取、提交当前上下文，服务端在持久化后广播 SSE。

**技术栈：** Node.js 原生 HTTP / ES modules、浏览器 JavaScript、现有原子 JSON 写入。

**设计：** `docs/superpowers/specs/2026-10-21-unified-project-linkage-design.md`

## 全局约束

- `数据/library.json` 是系列队伍、身份和名单的唯一权威。
- `数据/context.json` 是当前选择的持久化权威；`live.context` 只是服务端投影。
- 不在启动时自动迁移、覆盖冲突或删除旧数据；迁移先预览、再显式确认，并备份。
- 保持已有 URL、JSON 主结构、OBS 画面及推送语义。
- 不引入数据库、前端框架或运行时依赖。

## 审查重点

- `seriesId` 缺失或不存在：拒绝修改并返回可读错误。
- 旧 `teams.json` 与 canonical 队伍冲突：预览必须保留差异，不静默覆盖。
- 两个标签页提交相同 context revision：旧提交收到 409，当前服务端状态不回退。
- 服务端落盘失败：不更新 live 投影或 SSE，不降级写入 localStorage。
- 页面初始化或 SSE 更新：只读取服务端权威上下文，不自动发布旧值。

## 阶段一：契约盘点与统一队伍服务

- 将阶段盘点并入本阶段，更新设计状态、阶段编号与 `项目地图.md` 的数据权威/流向。
- 新建队伍领域模块：按 `seriesId` 读取和校验 `library.json`；整组替换只修改目标系列，保持其他系列和扩展字段。
- 新增 canonical team GET/PUT API；`/api/director/teams` 转为映射适配器，不再读写 `teams.json` 或隐式拼接两个来源。
- 提供 `teams.json` 差异预览与显式导入 API；冲突默认保留 library 值，导入未匹配队伍需给出目标系列，确认前无写入，确认时备份并幂等。
- 将导播台、工作台状态消费者切到 canonical API；完成后更新项目地图与使用说明。

## 阶段二：统一上下文与状态广播

- 新建上下文领域模块，负责初始化、revision 比对、引用校验、原子落盘和 revision 更新。
- 新增 GET/POST context API；旧 `/api/director/context` 适配到同一服务。
- 生成器用户明确选择后提交上下文；初始化读取只读。409 时提供采用最新值/继续提交本页选择的恢复入口；失败显示重试状态。
- `live.context` 只从持久化上下文初始化，并在保存成功后更新与广播；工作台和 OBS 消费该投影。
- 更新项目地图与使用说明。

## 阶段三：工作流导航

- 概览增加赛前、赛中、赛后建议步骤及数据就绪状态，不自动选择场次。
- 关键入口按 `seriesId`、`matchKey`、`gameId` 导航；保留侧栏和既有书签 URL。
- 检查失败状态、无当前场次、未匹配队伍和跨页面返回等流程；更新项目地图与使用说明。

## 阶段四：清理重复实现

- 全仓搜索旧页面、旧 API、localStorage 回退和构建引用，逐项确认依赖。
- 对浏览器旧 `pkc2_*` 数据提供只读差异预览和逐项显式导入；不自动合并或覆盖。
- 对仍被依赖的入口保留兼容并标注；只移除已确认无工作流引用的重复实现，不删除赛事数据或 `teams.json`。
- 汇总最终数据权威、迁移步骤与剩余兼容项。
