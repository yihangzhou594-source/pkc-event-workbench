# PKC 现场安全与紧凑工作台改进设计

日期：2026-10-23

状态：用户已批准六项范围，进入实施

## 1. 目标

在不改变现有数据协议、OBS 地址和蓝红语义的前提下，完成以下改进：

1. 导播台提供推送历史、撤回、空白画面确认和现场快捷键。
2. 概览与导播台显示逐场景预检状态，并在关键数据缺失时阻止误推送。
3. 对局数据页识别成功后收起重复工具区，待核对项先显示前 3 项，并补充重复与格式检查。
4. 精简淘汰赛页的重复说明，保留准确的操作规则和异常信息。
5. 提升 1080p 出图在直播压缩后的可读性，并说明雷达图的归一化方式。
6. 提供版本恢复、完整 JSON 导入导出和关键破坏性操作记录。

## 2. 导播安全

- 场景切换和设置编辑仍只改预览；推送才改变在播状态。
- 每次推送前记录当前在播场景与设置，最多保留 20 个回退点。
- 撤回推送恢复最近一次在播状态，并让预览同步到该状态。
- 从非空画面推送到空白画面时，界面要求二次确认；现场快捷键 `B` 作为紧急切空仍可直接执行。
- 快捷键保持 `1`—`6` 切场景、空格推送、`B` 紧急切空，并新增 `U` 撤回上一次推送。
- 服务端仍执行最终校验。预检阻断推送时必须显式提交 `force: true` 才能继续。
- 赛程图不因抽签尚未完成而阻断推送，以便直播展示实时抽签过程；只对同一队伍重复占位或同队对阵给出错误。

## 3. 场景预检

新增 `lib/production-readiness.mjs`，输入队伍库、对局、赛程和当前上下文，输出统一结构：

```text
status: ready | warning | blocked
scenes: [{ id, label, status, summary, blockers: [{ code, label, view }] }]
overall: { status, readyCount, total, firstBlocker }
```

- 解说 / 赛间：当前双方队伍存在，且双方名单各至少 5 人时为就绪。
- 赛程图：分组和对阵不完整时提示；重复队伍或同队对阵为阻断。
- 赛后数据图：当前局双方各 5 名选手和英雄完整时为就绪；比分、KDA 或经济可选字段缺失为提示。
- 宣传轮播：当前上下文和双方名单可用于初始化时提示就绪；手动名单仍在导播台编辑。
- 空白：始终就绪。

预检通过 `GET /api/director/readiness` 暴露，概览和导播台使用同一结果，避免两套判断。

## 4. 数据录入信息层级

- 导入区域拆成“识别工具”和“识别复核”两层。识别或粘贴成功后只收起工具层，复核结果保持可见。
- 提供“展开重新识别”，不丢失已有录入数据。
- 待核对清单先展示最先阻断出图的 3 项，其余放入可展开区域。
- 新增同场次重复局次、非法比分、非法时长检查。
- 点击问题仍定位到具体行或本局信息。

## 5. 赛程页面

- 分组、抽签和规则说明改为默认折叠的帮助内容，状态区和操作控件先显示。
- 每个步骤最多保留一条结果状态；异常名称直接列出，正常时只显示简短完成信息。
- 清空分组、清空对阵和清空赛果支持即时撤销，并写入操作记录。

## 6. 出图可读性

- 提高雷达图维度名、数值和核心对比条文字字号。
- 增加固定说明“每项以双方较高值为 100%”，避免把雷达形状误读成绝对数值。
- 输出尺寸、蓝红语义、现有 KPL 版式和全部字段保持不变。

## 7. 数据恢复与操作记录

- 原子写继续保留现有滚动备份。
- 新增备份列表与恢复接口，恢复前强制备份当前文件，避免恢复本身造成不可逆覆盖。
- 支持恢复 `library`、`matches`、`bracket`、`context`、`prefs`、`heroPick` 和 `heroStats`。
- 导出完整 JSON 备份；导入前校验版本、结构并显示覆盖范围，导入后保留当前文件备份。
- 关键批量清空、完整导入和版本恢复写入 `数据/_backup/audit.json`，界面展示最近记录。
- 删除、换人和批量导入继续走既有确认与撤销流程。

## 8. 兼容与验收

- 保持 `/`、`/director`、`/generator`、`/obs/*` 和 `?view=` 路由。
- 不改变赛事数据字段、OBS 1920×1080 尺寸或推送/丢弃语义。
- 单元测试覆盖播报状态回退、空白保护、预检规则以及备份列表/恢复。
- 浏览器验收覆盖场景预检、撤回按钮、数据导入折叠、赛程帮助折叠和恢复对话框。
- 全部回归测试通过，并生成至少一张 1920×1080 对位图做视觉检查。
