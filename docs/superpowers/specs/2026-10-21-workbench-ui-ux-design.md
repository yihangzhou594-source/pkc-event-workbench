# PKC 赛事工作台界面与交互优化设计

日期：2026-10-21

状态：书面规格已获用户审阅认可；实施计划待用户审阅

## 1. 目标

让赛事制作人员在工作台、数据页、赛程页、资料页、导播台和输出页面之间更容易理解当前上下文、找到下一步并确认操作结果。

成功后：

- 工作台是统一导航入口；用户切换页面时仍能确认当前系列赛、场次、小局、双方队伍和比分。
- 概览页按当前数据准备情况突出常见下一步，同时保留自由导航，不强迫线性流程。
- 不同页面使用一致的标题、上下文提示、主要操作和状态反馈，减少学习成本。
- 窄窗口和键盘操作仍能触达主要导航、赛事上下文和页面操作。
- 导播页面保留高密度现场操作；已建立的视觉主题和美术背景继续使用。

## 2. 现状与摩擦点

- 工作台侧栏已按工作、直播、数据、资料和输出分组，顶栏显示当前赛事上下文；概览页已有赛前、赛中、赛后入口。
- 数据引擎可在工作台 iframe 内使用，也保留独立页面内的标签导航。工作台侧栏和引擎内部导航均控制数据页，页面间存在双重导航概念。
- `assets/shell.css` 在窗口变窄时逐步隐藏标题说明、赛事上下文部分和侧栏文字；缩窄时信息虽让位于空间，但用户需要更多记忆或悬停才能确认含义。
- 外壳、数据引擎和导播操作各有控件风格与焦点状态。数据引擎已有输入焦点样式，工作台导航缺少统一、明显的键盘焦点指示。
- 保存、加载、空数据和失败反馈由各页面分别实现，提示位置与表达可能不一致。

本轮仅改善导航和交互的一致性，不改变领域数据协议、赛事流程规则或导播信号语义。

## 3. 设计选择

### A：建立一致的工作台交互层，再逐页改善（推荐）

保留现有页面和 URL，统一外壳导航、上下文提示、状态反馈与窄屏行为，然后按页面逐步整理层级。改动渐进，能保留已完成的领域联动和导播界面。

### B：逐页整体重做

可以对每页做更大幅度的视觉重构，但容易重新形成不同操作模式，且回归范围大。

### C：改成向导式工作流

可以强化新手引导，但会削弱熟练操作者自由跳转的能力，也不适合直播中的高频即时控制。

本设计采用 A：先统一交互规则，再逐页优化信息层级；不采用全站推倒重做或强制向导。

## 4. 导航与赛事上下文

- 工作台侧栏继续作为主导航，保留概览、导播台、对局数据、英雄胜率、赛程、队伍库、英雄图、宣传图、多局与导出、说明等现有入口及其 URL。
- 内嵌数据引擎不再呈现与工作台重复的主要导航；独立访问 `/generator` 时保留其可用导航。嵌入/独立模式沿用现有 `bare=1` 区分。
- 当前系列赛、场次、小局、双方队伍、比分和在播场景在工作台顶栏有统一展示。上下文不完整时提供直达选择页面的入口。
- 窄窗口下侧栏可以折叠，但折叠控件须可发现；图标有可访问名称或提示。顶栏上下文压缩为可打开的完整上下文面板，不丢失用户检查赛事身份所需的信息。
- 页面内跨页入口沿用稳定 ID 和现有上下文协议；除用户明确选择外，导航不得隐式切换当前赛事上下文或直播画面。
- 保持浏览器前进、后退、书签 URL 和 `?view=` 路由行为。

## 5. 页面信息层级

- 概览优先展示当前赛事状态、数据准备情况和与当前状态相关的下一步；每步直达对应页面。侧栏始终提供自由导航。
- 数据、赛程、队伍、英雄素材、英雄胜率、宣传图和导出页使用一致的页面标题、当前赛事提示、主要操作位置和结果反馈。
- 表单先呈现完成当前任务必需的字段；低频或高级选项可折叠，并保持其可发现性与值状态。
- 导播台维持现有预览、场景和现场操作的快速访问，不将直播控制改为分步向导。可改善分组、标签和状态提示，但不减少现场可见的关键控制。
- 沿用工作台现有深蓝、金色与浅色卡片视觉体系及已完成的导播背景美术素材；避免为了统一而抹平导播和数据编辑器的用途差异。

## 6. 状态、反馈与可访问性

- 常用读写流程统一表达加载中、空数据、保存中、保存成功和保存失败；失败提示包含可理解的原因或重试路径。
- 仅对确有风险的操作要求确认，例如删除、覆盖或会改变当前赛事上下文的操作；可以安全撤销时优先提供撤销。
- 所有按钮、标签、导航项和表单控件提供明显键盘焦点；导航状态和消息不能只依赖颜色传达。
- 窄屏布局应确保主要操作可访问，并提供有名称的折叠、展开入口；不将关键状态仅通过悬停提示呈现。
- 状态消息应在合适的语义区域中可被辅助技术读取，避免频繁、重复播报。

## 7. 兼容与边界

- 保持 `/`、`/director`、`/generator`、`/obs/*` 和现有 `?view=` 路由可用。
- 不改变队伍、赛程、对局数据、当前上下文的存储协议或数据主权设计。
- 不改变 OBS 输出尺寸、透明度、场景推送/丢弃语义或直播画面内容。
- 不引入前端框架、外部服务或运行时依赖。
- 不强制用户按赛前→赛中→赛后顺序操作。

## 8. 验收标准

- 工作台内浏览数据引擎时只有一套主导航；独立访问生成器时仍可导航。
- 每个页面都能明确识别当前视图和当前赛事上下文；上下文不完整时可直达选择操作。
- 在常见桌面与窄窗口尺寸下，导航和主要赛事上下文可发现、可操作。
- 通过键盘可操作主导航、上下文选择入口和主要页面控件，并能清楚看到焦点。
- 主要读写页面对加载、空状态、成功和失败给出一致且可理解的反馈。
- 概览入口和侧栏切换不意外更改当前赛事上下文或直播画面；浏览器历史与旧书签仍正常。
- 导播台仍能快速访问现场场景控制，现有输出与画面语义不变。

## 9. 实施顺序建议

1. 统一外壳与内嵌生成器导航的职责，完善当前上下文的窄屏呈现与页面标题状态。
2. 统一全局键盘焦点、按钮/链接状态和跨页面导航反馈。
3. 逐页改善概览、数据录入、赛程、资料、统计、宣传图和导出页面的信息层级及状态反馈。
4. 最后检查导播台的现场快速操作、不同窗口尺寸和独立入口兼容性。

每阶段以针对性页面检查和必要回归验证确认结果；不为完成视觉改动而更改真实赛事数据。
